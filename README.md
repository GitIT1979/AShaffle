# AShuffle

Одностраничное приложение (один HTML-файл): возвращает трекам их истинные имена и перемешивает их так, чтобы рядом не оказывались песни одного исполнителя.

Версия: **v11.67**

## Быстрый старт

Открывать нужно **через локальный сервер**, а не двойным кликом: со страницы `file://` браузер режет запросы к Deezer, iTunes и MusicBrainz, и проверка названий молча ничего не находит.

```
cd D:\AI_projects\AShaffle\AShaffle_HTML
python -m http.server 8123
```

Затем открыть <http://127.0.0.1:8123/AShaffle.html>.

## Десктопная версия (Windows)

В `AShaffle_desktop/dist/` лежит `AShaffle_desktop.exe` — тот же код в окне WebView2.
Файлы рядом не нужны: при старте приложение само поднимает сервер на
`127.0.0.1` и открывает окно. Возможности те же, что у HTML-версии, включая
«Сохранить все в папку». Пересборка: `AShaffle_desktop/build.bat`
(pywebview + pyinstaller, веб-ресурсы зашиваются внутрь exe).

## Два шага

1. **🪄 Make this true!** — проверяет каждое название в интернете, показывает результат в исходном порядке и без нумерации. Отсюда можно скачать как отдельные файлы, так и всю папку (или ZIP).
2. **OK** — рабочий список и кнопки скрываются, остаётся список исправленных имён. Ниже — «Скачать все в папку» и **🎲 Ashuffle this!**: перемешивание с нумерацией `001…`.

Проигрывание: кнопка ▶ в строке рабочего списка (одновременно играет только один трек). Кнопка **⇄ n/m** появляется, когда у названия есть несколько равноценных кандидатов: лучший уже применён, остальные — одним нажатием.

## Реестр правил

Все правила обработки имён собраны в одном месте — массив `RULES` в начале скрипта (`AShaffle_HTML/js/00-core.js`). У каждого правила есть номер, слой, текст и функция (или константа), которая его реализует. Посмотреть список прямо в браузере:

```js
__ashuffleRules()
```

Правило считается действующим, только если у него есть живой код и тест: `test/harness.js` проверяет привязку, `test/rules.js` — поведение.

### Вход: имя файла и теги

| № | Правило | Код |
|---|---|---|
| 1 | Номер трека в начале имени (`001 - `, `07. `) отрезается, но число внутри названия остаётся | `stripTrackPrefix` |
| 2 | Мусорные латинские префиксы сайтов (`KR`, `TV`, `AQF`, `UYT`, `nai`) срезаются до остальных чисток | `stripNamePrefix` |
| 3 | Латинские буквы-двойники внутри кириллических слов (`Vиктор` → `Виктор`) | `foldMixed` |
| 4 | Диакритика не важна: `mêmes` = `memes`, `Tiësto` = `Tiesto`, `ё` = `е` | `norm`, `tokens` |
| 5 | Сайты-водяные знаки в скобках и без (`Sefon.me`, `музыка.me`, `sonq.ru`) вырезаются | `stripSiteJunk` |
| 6 | Шум в скобках (`remaster`, `bonus`, `radio edit`) не часть названия | `stripNoiseBrackets` |
| 7 | Два и более дефиса внутри слова — разделители (`the-black-eyed-peas-j-balvin`) | `splitGluedArtist` |
| 8 | Одиночная буква, приклеенная к имени (`MДжанго`), отбрасывается | `shaveGluedLetter` |
| 9 | Кредит, застрявший в названии (`and halsey - …`), возвращается исполнителю | `pullCreditFromTitle` |
| 10 | Заглушка (`unknown_artist`, `VA`) и непроизносимое имя (`花電車`) — не исполнитель | `isPlaceholder` |
| 11 | Теги важнее имени файла: ID3v2, ID3v1, FLAC, m4a, Ogg/Opus, APE, WMA | `readMp3Tags` |
| 12 | Словарь имён групп и связок (`korol i shut`, `жанго`) — знание, а не догадка | `aliasSplit` |
| 13 | Имя строчными тоже запрашивается с заглавной (`жанго` → `Джанго`) | `capitalizeArtist` |
| 14 | Артикль `The` из файла возвращается, если каталог его потерял | `keepArticle` |

| № | Правило | Код |
|---|---|---|
| 21 | Допуск по длительности ±10 с; при полном совпадении имени ±60 с | `DUR_TOL`, `DUR_TOL_EXACT` |
| 22 | Балл ниже 0.5 — случайное совпадение, кандидат отбрасывается | `MIN_SCORE` |
| 23 | Исполнитель сверяется с файлом, включая транслитерацию | `isGoodMatchFlex` |
| 24 | Без исполнителя каждый шаг обязан подтвердить ещё и название | `lookupTrack` |
| 25 | Название кандидата должно состоять только из слов файла | `tailOk` |
| 26 | Ремиксы, каверы, караоке, мэшапы не принимаются, если их нет в запросе | `SUSPICIOUS` |
| 27 | Кредит файла сохраняется, только если лишний участник значимый (не `the`) | `creditGaps` |

## Как это работает на практике

1. **Теги важнее имени файла.** Значения тегов проходят ту же чистку, что и имя: префиксы, двойники, сайты, шум.
2. **Длительность** берётся из метаданных `<audio>` (запасной путь — `TLEN`/`STREAMINFO`) и служит фильтром.
3. **Словарь** спрашивается сразу после основного запроса: он не догадка, а знание.
4. **Обратный транслит** идёт после точных запросов: он не должен отбирать время у честного поиска.
5. **Спорные случаи.** Когда в тегах сдвинута граница слов, работает правило хвоста: первое слово исполнителя плюс последние слова названия. Кандидат принимается, только если его название состоит из слов файла.
6. **Если ничего не нашлось** — имя остаётся как было, в строке появляется «✎ исправить», а для файлов без данных — значок «нет данных».

Запуск проверок:

```
node test/harness.js
```

## Ограничения

- **Распознавания по звуку нет** — направление отклонено сознательно; идентификация идёт по тегам, имени и длительности.
- **MusicBrainz** почти не содержит русскую поп-музыку; для неё основные источники — Deezer и Apple.
- **Словарь переводов имён** небольшой; редкие имена дополняются вручную.
- **Мэшапы и раритеты** (`DJ Five`, `Whos Laughing`, `Baladrì`) в каталогах отсутствуют — такие файлы остаются с пометкой «исправить».
- **Файлы без тегов и с бессмысленным именем** (`unknown_artist - unknown_track`) не распознаются: имени нет, угадывать нечем.
- **ZIP** собирается в памяти и не поддерживает ZIP64: архив больше 2 ГБ или свыше 65 535 файлов — понятная ошибка, а не битый файл (предел в 2 ГБ — с запасом: буфер целиком живёт в памяти вкладки).
